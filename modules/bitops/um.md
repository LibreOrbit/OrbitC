# Bitops Module User Manual

## Overview

The OrbitC Bitops module provides safe and portable bit manipulation utilities for embedded and flight software.

It supports single\-bit operations, bitfield extraction and insertion, rotations, bit reversal, population count, parity, and bit scanning while avoiding undefined behavior associated with invalid shifts or bit indexes.

Both 32\-bit and optional 64\-bit operations are supported.

## Dependencies

The Bitops module depends on the following OrbitC modules:

- types
- status

They must be enabled before using the module.

## Configuration

The module is configured at compile time through bitops\-config.mk.

The main configuration options are:

| Option | Description |
| --- | --- |
| ORBITC\_BITOPS\_BACKEND | Selects the implementation backend. |
| ENABLE\_BITOPS\_64 | Enables or removes 64\-bit operations. |

64\-bit support can be disabled when not required:

ENABLE\_BITOPS\_64 = 0

This removes the associated API from the build and can reduce the final binary footprint.

## Backend Selection

Two implementation backends are available:

- ORBITC\_BITOPS\_BACKEND\_PORTABLE: pure C99 implementation using portable bitwise and SWAR algorithms.
- ORBITC\_BITOPS\_BACKEND\_BUILTIN: uses GCC/Clang compiler intrinsics when available.

The active backend can be queried at runtime using:

orbitc\_bitops\_active\_backend();

The portable backend should be preferred when compiler independence or predictable generated code is required.

The builtin backend can take advantage of target\-specific instructions generated by the compiler.

## Single\-Bit Operations

Individual bits can be safely manipulated using:

orbitc\_bit32\_set(&word, bit);

orbitc\_bit32\_clear(&word, bit);

orbitc\_bit32\_toggle(&word, bit);

The state of a bit can be queried using:

bool\_t is\_set;

status\_t status = orbitc\_bit32\_test(word, bit, &is\_set);

Bit indexes are checked at runtime and must be within 0..31.

Equivalent 64\-bit functions are available when ENABLE\_BITOPS\_64=1.

## Bitfields

Bitfields can be extracted from hardware registers or packed data:

ui32\_t value;

status\_t status = orbitc\_bitfield32\_extract( word, offset, width, &value);

A value can be inserted into an existing field using:

orbitc\_bitfield32\_insert(&word, offset, width, value);

The field value is automatically masked to the requested width.

Runtime functions validate the field geometry and reject invalid offsets or widths.

## Compile\-Time Bit Masks

For constant and already validated bit positions, lightweight macros are available:

ORBITC\_BIT32(5U)

ORBITC\_BIT64(12U)

Contiguous 32\-bit masks can be generated using:

ORBITC\_BITMASK32(offset, width)

These macros do not perform runtime validation and should only be used with known\-valid constant parameters.

## Rotations and Bit Reversal

32\-bit rotations are available through:

orbitc\_rotl32(word, shift, &result);

orbitc\_rotr32(word, shift, &result);

Rotation counts are automatically reduced modulo 32, allowing any ui8\_t shift value without invoking undefined shift behavior.

A 32\-bit word can also be bit\-reversed using:

orbitc\_bitrev32(word, &result);

Equivalent rotation operations are available for 64\-bit values when 64\-bit support is enabled.

## Bit Scanning

The module provides common bit\-analysis operations:

orbitc\_popcount32(word, &count);

orbitc\_clz32(word, &count);

orbitc\_ctz32(word, &count);

orbitc\_parity32(word, &parity);

These operations provide:

- population count / Hamming weight;
- leading\-zero count;
- trailing\-zero count;
- odd/even bit parity.

orbitc\_clz32() and orbitc\_ctz32() require a non\-zero input and return BITOPS\_CODE\_ZERO\_INPUT otherwise.

Equivalent population and zero\-count operations are available for 64\-bit values when enabled.

## Safety

Runtime Bitops functions validate operations before performing potentially unsafe bit manipulation.

The module detects:

- null output pointers;
- invalid bit indexes;
- invalid bitfield offsets or widths;
- zero inputs for operations requiring non\-zero values.

Errors are reported through the OrbitC status\_t mechanism.

## Usage Guidelines

Use the runtime API when bit positions or field dimensions originate from runtime data:

orbitc\_bit32\_set(&reg, bit\_index);

Use the compile\-time macros when parameters are known and guaranteed to be valid:

reg \|= ORBITC\_BIT32(4U);

For hardware register manipulation, prefer the bitfield extraction and insertion functions when field geometry is dynamic or requires explicit validation.

For performance\-critical fixed register definitions, compile\-time masks remain the lowest\-overhead option.
